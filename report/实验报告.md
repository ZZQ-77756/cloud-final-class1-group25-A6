## 1. 摘要

本项目旨在解决传统 Web 应用部署中环境不一致、依赖管理复杂以及手动部署效率低下的问题。我们采用 Ubuntu 虚拟机作为基础设施，从基础的单体 Nginx 容器化入手，逐步演进为基于 **Docker Compose** 的**微服务架构**。

关键功能包括：
1.  **基础容器化**：编写 `Dockerfile` 实现 Nginx 镜像的标准化构建与版本管理。
2.  **自动化运维**：使用 Shell 脚本（`run.sh`）实现“一键自动化部署”与热更新。
3.  **微服务编排**：利用 Docker Compose 编排 Nginx（前端）、Flask（后端）与 Redis（数据库）三个容器，实现了前后端分离与数据持久化。

---

## 2. 需求与目标

* **背景与问题描述**：在传统部署模式下，Nginx、Python 环境和数据库的安装配置极其繁琐，且容易出现“在我的机器上能跑”的环境差异问题。
* **功能目标（必须项）**：
    * **目标1**：编写 `Dockerfile` 构建自定义 Nginx 镜像。
    * **目标2**：实现容器端口映射（Host:8080 -> Container:80）与环境变量注入。
    * **目标3**：实现宿主机目录挂载，使得修改本地文件能即时反映在容器网页中。
* **进阶目标（加分项）**：
    * **目标4**：引入 **Docker Compose** 进行多容器编排。
    * **目标5**：构建 **Nginx + Python Flask + Redis** 的三层微服务架构，演示反向代理与数据库连接。
* **不做的范围**：本项目不涉及 Kubernetes 集群编排，仅关注单机 Docker 容器管理。

## 3. 相关概念与原理

1.  **容器化 (Containerization)**
    * **解释**：将应用及其依赖打包在一起，实现“一次构建，到处运行”。
    * **体现**：使用 Docker 分别打包了 Web 服务器和应用服务器，消除了环境差异。

2.  **容器编排 (Container Orchestration)**
    * **解释**：自动化管理多个容器的生命周期、网络连接和依赖关系。
    * **体现**：使用 `docker-compose.yml` 定义了 web、backend、redis 三个服务的启动顺序（`depends_on`）和网络互通。

3.  **微服务架构 (Microservices)**
    * **解释**：将单体应用拆分为一组小型服务，服务间通过轻量级机制（如 HTTP API）通信。
    * **体现**：Nginx 负责静态页面和反向代理，Python Flask 负责业务逻辑（计数），Redis 负责数据存储。

```plaintext

     |

                                        |

                                   [Redis 容器 (数据库)]

```

## 6. 实现过程

### 6.1 准备工作

* **环境检查**：确认 Docker 服务已启动 (`systemctl status docker`)。
* **工具安装**：安装 Docker Compose 插件 (`sudo apt install docker-compose-plugin`)。

### 6.2 阶段一：基础 Nginx 容器化（使用 run.sh）

**步骤 1：编写 Dockerfile**
我们将官方 Nginx 镜像作为基础，并配置默认文件路径。

```dockerfile
FROM nginx:latest
COPY src/index.html /usr/share/nginx/html/index.html

```

**步骤 2：编写自动化脚本 run.sh**
为了解决手动输入长命令容易出错的问题，封装了构建和运行逻辑。

```bash
# ... (脚本逻辑省略，见源码)
docker run -d -p 8080:80 -v "$(pwd)/src":/usr/share/nginx/html ...

```

**步骤 3：部署 v1 版本**
运行 `./run.sh v1`，脚本自动构建并启动容器。

### 6.3 阶段二：微服务架构改造（使用 Docker Compose）

为了提升架构的可扩展性，我们引入了 Python 后端和 Redis 数据库。

**步骤 1：编写后端服务 (backend/app.py)**
使用 Flask 框架编写 API，连接 Redis 记录访客数量。

```python
@app.route('/api/hello')
def hello():
    count = r.incr('hits') # Redis 计数器 +1
    return jsonify({"message": "Hello...", "visit_count": count})

```

**步骤 2：配置 Nginx 反向代理 (nginx/default.conf)**
配置 Nginx 将 `/api/` 开头的请求转发给后端容器。

```nginx
location /api/ {
    proxy_pass http://backend:5000;
}

```

**步骤 3：编写编排文件 (docker-compose.yml)**
定义三个服务：`web` (依赖 backend), `backend` (依赖 redis), `redis`。

```yaml
services:
  web:
    image: nginx:latest
    ports: ["8080:80"]
    depends_on: [backend]
  backend:
    build: ./backend
    depends_on: [redis]
  redis:
    image: redis:alpine

```

**步骤 4：一键启动微服务**
使用命令 `sudo docker compose up -d --build` 启动整个集群。

## 8. 运维与排错 (Troubleshooting)

在实验过程中，我们记录了以下真实的排错经历：

### 问题 1：构建镜像时拉取 Alpine 层超时

* **现象**：尝试做“镜像瘦身”时，基础镜像下载卡死。
* **解决方法**：配置 Plan B，暂时使用本地缓存的 `latest` 镜像，并尽可能利用 Python 的清华源 (`-i https://pypi.tuna.tsinghua.edu.cn/simple`) 加速依赖安装。

### 问题 2：Docker Compose 命令不存在

* **现象**：运行 `docker-compose` 报错 `Command not found`，尝试 `apt install` 安装旧版本后又报错 `Python connection error`。
* **根因**：旧版 `docker-compose` (Python版) 与系统库冲突。
* **解决方法**：
1. 卸载旧版本。
2. 手动下载官方二进制文件 `docker-compose-linux-x86_64` (v2.24.5)。
3. 移动到 `/usr/local/bin` 并赋予执行权限，成功解决。



### 问题 3：前端无法显示后端数据

* **现象**：微服务启动成功，但网页仍显示旧版内容。
* **根因**：Docker 挂载的是宿主机的 `src/index.html`，但该文件未更新包含 JS 逻辑的代码。
* **解决方法**：修改宿主机 `src/index.html`，添加 `fetch('/api/hello')` 的前端代码。
